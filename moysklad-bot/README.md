# Telegram-бот учёта для цеха (МойСклад)

Бот для 5 сотрудников: приём расходов, доходов, отгрузок и прочих расходов прямо
в Telegram, с автоматической записью в уже существующий аккаунт МойСклад.

Владелец и директор получают **автоматический отчёт каждый день** (доход,
расход и остаток кассы) прямо в Telegram, плюс могут запросить его в любой
момент командой `/balance` (или `/today`). **Обычные сотрудники цифр по
доходу и расходу не видят вообще** — им по той же команде доступен только
текущий остаток кассы.

## Интерфейс

У бота закреплённое меню внизу экрана (как панель вкладок в обычном
приложении) — оно всегда на виду, не нужно листать переписку в поисках
кнопок: **💸 Расход · 💰 Доход · 📦 Отгрузка · 🧾 Прочий расход · 📊 Баланс**.
Кнопку можно нажать в любой момент, даже посреди ввода другого действия —
бот сам отменит текущий шаг и начнёт новый.

## Как это работает

- Сотрудник нажимает кнопку в закреплённом меню «Расход / Доход / Отгрузка / Прочий расход / Баланс».
- Расход/доход/прочее → бот создаёт **расходный или приходный кассовый ордер**
  (`entity/cashout`, `entity/cashin`) в МойСклад с суммой и комментарием.
- Отгрузка → бот просит выбрать (или создать) клиента и один или несколько
  товаров из вашего каталога МойСклад, затем создаёт документ **«Отгрузка»**
  (`entity/demand`).
- Все записи попадают в тот же аккаунт МойСклад, которым вы пользуетесь 5 лет —
  ничего не дублируется, отчёты смотрите там же, где привыкли.

## Шаг 1. Получить токен Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram → `/newbot`.
2. Задайте имя и username бота.
3. Скопируйте выданный токен вида `123456789:AAAA...` — это `BOT_TOKEN`.

## Шаг 2. Получить API-токен МойСклад

1. Зайдите в МойСклад → **Настройки аккаунта → Обмен данными → API**.
2. Создайте токен доступа (или используйте логин/пароль — но токен надёжнее).
3. Это `MOYSKLAD_TOKEN`.

JSON API бесплатен на всех тарифах, включая бесплатный — регистрироваться отдельно
не нужно.

## Шаг 3. Узнать Telegram ID владельца, директора и сотрудников

Каждый должен написать боту [@userinfobot](https://t.me/userinfobot) — он пришлёт
числовой ID. Соберите ID владельца, директора (если есть) и всех 5 сотрудников.

## Шаг 4. Настроить и запустить

```bash
cd moysklad-bot
cp .env.example .env
# впишите в .env: BOT_TOKEN, MOYSKLAD_TOKEN, OWNER_IDS, DIRECTOR_IDS, EMPLOYEE_IDS
```

### Вариант А: локально / на своём сервере

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m bot.main
```

### Вариант Б: Docker (рекомендуется для постоянной работы)

```bash
docker compose up -d --build
```

Бот будет автоматически перезапускаться при сбоях (`restart: unless-stopped`).

Чтобы бот работал круглосуточно, его нужно разместить на сервере (подойдёт
самый дешёвый VPS, ~$3–5/мес) — просто на своём компьютере он будет отвечать,
только пока открыт терминал.

## Шаг 5. Развернуть на сервере, чтобы бот работал 24/7

Бот работает через long polling (сам опрашивает Telegram), поэтому **не
нужно** ни открывать порты, ни настраивать домен/SSL — нужен только сервер с
исходящим доступом в интернет.

### 5.1. Арендовать VPS

Минимум: 1 vCPU, 512 МБ–1 ГБ RAM, Ubuntu 22.04/24.04 — этого более чем
достаточно. Варианты:
- Проще с оплатой из СНГ: Timeweb Cloud, REG.RU, Selectel — от ~150–250 ₽/мес.
- Международные (нужна карта с поддержкой валютных платежей): Hetzner
  (~€4/мес), Vultr, DigitalOcean, Contabo.

После оплаты провайдер пришлёт IP-адрес и пароль (или SSH-ключ) на почту.

### 5.2. Подключиться и поставить Docker

```bash
ssh root@ВАШ_IP
curl -fsSL https://get.docker.com | sh
```

### 5.3. Загрузить код бота на сервер

Через git (если репозиторий доступен с сервера):
```bash
git clone <URL_репозитория>
cd powermix-site/moysklad-bot
```

Или просто скопировать папку со своего компьютера:
```bash
scp -r moysklad-bot root@ВАШ_IP:/root/
ssh root@ВАШ_IP
cd moysklad-bot
```

### 5.4. Настроить .env и запустить

```bash
cp .env.example .env
nano .env   # впишите реальные BOT_TOKEN, MOYSKLAD_TOKEN, OWNER_IDS, DIRECTOR_IDS, EMPLOYEE_IDS
docker compose up -d --build
```

### 5.5. Проверить, что бот работает

```bash
docker compose logs -f
```
(должна быть строка `Starting bot: ...`; `Ctrl+C` выходит из просмотра логов,
сам бот продолжает работать в фоне).

### 5.6. Автозапуск после перезагрузки сервера

- `restart: unless-stopped` в `docker-compose.yml` сам перезапускает
  контейнер при падении или перезагрузке.
- Убедитесь, что Docker стартует вместе с системой:
  ```bash
  systemctl enable docker
  ```

### 5.7. Обновление бота после изменений в коде

```bash
git pull        # или заново scp -r
docker compose up -d --build
```

## Доступ и кто что видит

Отвечать боту могут только те, чей Telegram ID указан в `OWNER_IDS`,
`DIRECTOR_IDS` или `EMPLOYEE_IDS` в `.env`. Все остальные получат отказ.

Все три роли (владелец, директор, сотрудник) могут вносить расход/доход/
отгрузку/прочее — это не ограничено. А вот команда `/balance` (алиас
`/today`) показывает разное в зависимости от роли:

| Роль | Что видит по `/balance` | Ежедневный автоотчёт |
|---|---|---|
| Владелец (`OWNER_IDS`) | Доход, расход и остаток кассы | Да, каждый день |
| Директор (`DIRECTOR_IDS`) | Доход, расход и остаток кассы | Да, каждый день |
| Сотрудник (`EMPLOYEE_IDS`) | Только остаток кассы, без сумм дохода/расхода | Нет — только по запросу |

## Остаток кассы и ежедневный отчёт

- Каждый день в `DAILY_REPORT_TIME` (по умолчанию 20:00, время сервера) бот
  сам присылает владельцу и директору: доход и расход за сегодня + текущий
  остаток кассы. Ничего запрашивать не нужно. Сотрудникам этот отчёт не
  приходит.
- Остаток бот пытается взять из встроенного отчёта МойСклад
  «Остатки по счетам/кассам» (`/report/money/byaccount`). Если этот отчёт
  недоступен на вашем тарифе — бот автоматически считает остаток сам, суммируя
  все приходные и расходные кассовые ордера за всё время. Это чуть медленнее
  при очень долгой истории, но работает без дополнительной настройки.

## Важно проверить перед боевым использованием

Код написан по документированной схеме JSON API МойСклад
(`https://dev.moysklad.ru/doc/api/remap/1.2/`), но у каждого аккаунта могут
быть свои обязательные поля (обязательные доп. поля, статьи расходов,
несколько организаций/складов и т.п.). Обязательно:

1. Заведите тестового сотрудника (свой Telegram ID) и проверьте все 4 сценария
   на реальном аккаунте МойСклад перед тем как раздавать доступ команде.
2. Если МойСклад вернёт ошибку валидации — она придёт прямо в чат с текстом
   ошибки от API; это подскажет, какое поле нужно доработать в
   `bot/moysklad.py`.
3. Если у вас несколько юрлиц или складов — сейчас бот берёт первую
   организацию и первый склад из списка (`get_default_organization_href`,
   `get_default_store_href`). При необходимости можно легко изменить на явный
   выбор из настроек.

## Структура проекта

```
moysklad-bot/
├── bot/
│   ├── config.py         # чтение .env
│   ├── moysklad.py       # клиент JSON API МойСклад
│   ├── keyboards.py      # inline-клавиатуры
│   ├── states.py         # состояния диалогов (FSM)
│   ├── main.py           # точка входа, контроль доступа
│   └── handlers/
│       ├── start.py      # /start, главное меню
│       ├── cash.py       # расход / доход / прочий расход
│       ├── shipment.py   # отгрузка (клиент + товары)
│       └── report.py     # /balance, /today — отчёт по роли
├── requirements.txt
├── .env.example
├── Dockerfile
└── docker-compose.yml
```
